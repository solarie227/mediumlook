# 中判ルック for Mac（v0.2）

iPhoneの写真に、「6×7 80mm F2.8で撮ったら、この距離ならこれだけボケる」という量のボケを計算してかけるMacアプリです。

## できること

- 写真を開く：⌘O、ウインドウへのドラッグ＆ドロップ、写真ライブラリ
- 画像をクリックした位置にピントを合わせ、フォーマットとF値から計算した量のボケをかける
- 開いたときのピント位置は自動で決める：①撮影時にピントを合わせた範囲（EXIF SubjectArea。中央の広い初期値は除く）→ ②いちばん大きい顔の目のあたり（Vision）→ ③中央。何から決めたかは「情報」に出る。ピント位置は元の写真の座標で持つので、フォーマットや画角を変えても同じ被写体に合ったまま
- ポートレートモードの写真では、人物マスクの内側を指したとき、マスクの内側だけでピント面の深度を読む（髪の隙間から見える背景を拾わない）
- 深度の取り方は2通り
  - **写真の深度**：iPhoneが人物・ペットの写真やポートレートモードの写真に記録した深度
  - **推定**：深度データがない写真（風景、物、チャットで送られた写真など）は、AppleのCore ML版 Depth Anything V2 Small で推定します。初回だけ「推定モデルを導入」を押してください（約50MB、Apache-2.0）
- 「輪郭を写真に合わせる」：低解像度の深度を、写真の明暗の境目に沿うように引き伸ばす（Core Image の CIEdgePreserveUpsampleFilter）。被写体の縁がボケたり、縁の外の背景がボケずに残ったりするのを減らす。「合わせ方」で追従の細かさを変えられる
- 「画角を合わせる」：換算焦点距離の比で中央を切り出す（26mm → 6×7 80mmの換算約39mmで約1.49倍、比率4:5）
- **フィルムの質感**（右の「フィルム」）：Portra 400風・Ektar 100風・Pro 400H風・Velvia 50風・Tri-X 400風から選ぶ。実在のフィルムを測ったものではなく、スキャンでよく見る傾向に目で合わせた近似
  - 色のくせ（3×3行列）、S字の階調、黒の浮き・白の抑え、彩度、暗部と明部の色味
  - 粒状：粒子の大きさをフィルム上のμmで持ち、フォーマットの対角長で画素に直す。同じフィルムでも6×7は35mm判の約半分の細かさになる。粒子が1画素より小さいときは、画素の中で平均されるぶん弱くする
  - ハレーション：とても明るい部分のまわりに赤みのある光を足す
  - 「色と階調」でかかり具合、「粒状」「ハレーション」で強さを調整できる
- 周辺減光（「仕上げ」）：フィルムを選ばなくてもかけられる
- 深度がない写真でも、フィルムの質感だけかけて表示・書き出しできる
- 表示の切り替え：仕上がり ⌘1 ／ 元画像 ⌘2 ／ 深度 ⌘3
- **フル解像度で書き出し**（⌘E）。拡張子で形式が決まります：`.jpg` ／ `.heic` ／ `.tif`（16bit）

## ビルドと起動

必要なもの：macOS 14以降、Apple シリコンのMac、Xcode（または Command Line Tools）

### A. Xcodeで開く（試しながら直すとき）

1. `Package.swift` をダブルクリックしてXcodeで開く
2. 上部のスキームが `MediumLook`、実行先が `My Mac` になっていることを確認
3. ⌘R で起動

### B. アプリ（.app）にする（普段使いするとき）

ターミナルでこのフォルダに移動して：

```
./build_app.sh
```

`build/MediumLook.app`（表示名「中判ルック」）ができます。アプリケーションフォルダにコピーして使えます。自分のMac用のアドホック署名なので、他の人のMacで動かすには別途署名と公証が必要です。

## 使い方

1. 写真を開く
2. 深度データがない写真の場合は、右の「深度」で推定モデルを導入する（初回のみ）
3. 被写体の目などをクリックしてピントを合わせる
4. 推定深度のときは「ピント位置までの距離」を実際の撮影距離に合わせる（推定した深度には単位がないため、ボケの量はこの距離で決まります）
5. F値やフォーマットを変えて比べ、⌘Eで書き出す

## 計算のしくみ

錯乱円の直径（フィルム上）：

```
b = f² / (N(s − f)) × |d − s| / d
```

視差 D = 1/d、ピント面の視差 Ds = 1/s とすると `b = b∞ × |1 − D/Ds|`（b∞ = f²/(N(s − f))）。b をフォーマットの対角長（6×7なら89.6mm）で割り、画像の対角ピクセル数を掛けたものがボケの直径です。

推定深度は「手前ほど大きい相対値」なので、D/Ds の比はそのまま使え、b∞ を決めるピント距離 s だけをユーザーが指定します。

ハイライトは、ボケの計算の前に E(x) = x/(1−kx) で広げ、計算後に C(y) = y/(1+ky) で戻しています（k = boost/(1+boost)）。曇り空のような広い明るい部分は元の明るさに戻り、小さな光だけがボケの中で玉として残ります。

ボケは画素ごとにまわりの画素を集めて作る。そのとき「ピント面より手前（前ボケ）」と「ピント面とその奥」を別の層に分け、最後に重ねる。
- 前ボケの層：手前でボケている画素は、どの画素の上にも、自分のボケの大きさで半透明に広がる。その点を覆っている割合を不透明度にする。こうすると手前の物の縁の内側にも後ろが透けて見え、本物のレンズのように縁がやわらかくなる
- 後ろの層：奥の画素は、手前のピントが合った画素の上には広がれない。中心が前ボケのときは、手前の物の陰に見えているはずの背景を、まわりの奥の画素から推し量る
- ボケの円の縁は、大きさに応じて少しやわらかくする（硬いコインのように見えないように）
- 「前ボケの量」で、ピント面より手前のボケだけを弱められる。推定した深度では手前の物の距離がずれやすいため

## iPhone版プロトタイプとの違い

- 深度がない写真でも推定でボケをかけられる
- フル解像度で書き出せる（GPUのタイムアウトを避けるため、256行ずつの帯に分けて処理）
- Metalシェーダーは実行時にコンパイル（Swift Packageでそのままビルドできるようにするため）

## 既知の制限

- 被写体の輪郭（髪の毛など）は、深度の解像度が低いのでにじむことがある（「輪郭を写真に合わせる」で軽減。被写体と背景の明るさが近いところでは効きにくい）
- 書き出し時にEXIF（撮影日時・位置など）は引き継がない
- フィルムの色はiPhoneの処理済みの画像（HEIF/JPEG）から作るので、白飛び・黒つぶれした部分の階調は戻らない

## うまく動かないとき

- **`SwiftUIMacros` が見つからないというエラー**：Xcode本体ではなく Command Line Tools でビルドされています。`build_app.sh` はXcodeがあれば自動でそちらを使います。手で切り替えるなら `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
- **ビルドエラーが出る**：エラー文をそのまま貼ってください
- **推定モデルの導入に失敗する**：ネットワークを確認してください。モデルは `~/Library/Application Support/MediumLook/` に置かれます
- **推定した深度の明暗が逆**（深度表示で奥が明るい）：モデルの出力の向きが想定と違います。教えてください
- **仕上がりが上下逆になる**：`RenderEngine.swift` の `readTexture` の戻り値に `.oriented(.downMirrored)` を付けてください（想定どおりなら不要です）
